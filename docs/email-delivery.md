Keep the desktop workbench, Manrope, blue actions and amber HITL checkpoint. Add an inline project-email connection disclosure in HITL, a dry-run/live-email review choice, an exact sender/footer preview, and read-only delivery receipts. The SendGrid adapter is off by default and ignores generic/personal keys. Each business needs an explicitly enabled project sender ID/from address and unsubscribe group; identities/groups cannot be shared between enabled businesses. A signed-event public key is required. Sender identity, reply address, postal footer and unsubscribe group are retrieved, shown, and explicitly confirmed. Live-message approval includes the exact sender and plain-text body with postal footer and the provider unsubscribe substitution. Tracking is disabled. No lookup confirms consent, buyer authority, or inbox delivery.

Immediately before a single POST, recheck sender identity, provider global/group suppression, account/profile/source freshness, local preferences, exact live approval and credit gates. Persist the immutable attempt before transmission. HTTP 202 establishes provider acceptance only. Definitive rejection refunds local credits and requires fresh approval; ambiguous responses/timeouts and interrupted transmission retain a pending reservation and locked unknown attempt. They never replay automatically. A dry-run approval cannot authorize live email. Alternate variants cannot bypass a pending/unknown attempt.

Signed raw-byte ECDSA event receipts bind the random dispatch ID, business, recipient and provider message identity. Duplicates and out-of-order events do not repeat debit or pipeline advancement. Delivery, deferral, failure and unsubscribe events remain distinct from replies. Provider opt-outs/complaints/bounces restrict future address processing; manual release cannot remove them. Accepted attempts and suppression history survive campaign reset so late events cannot recreate deleted accounts or lose opt-outs. Pending/unknown transmission prevents reset. No automatic resend or unknown-outcome timeout refund is offered: operator/provider investigation is required when no signed receipt arrives.

## Project setup

The main workspace keeps live delivery disabled. Setup requires a deliberately designated project SendGrid account, a protected HTTPS deployment and a controlled test recipient. Do not use personal/global credentials or treat configuration as a verified connection.

1. Configure `PROJECT_ACCESS_TOKEN` with a non-placeholder project token of at least 24 characters and `PUBLIC_ORIGIN` with the exact HTTPS origin. Keep the webhook route reachable through the deployment proxy. Its signed-event authentication is separate from browser sessions; every other project API route retains session/CSRF checks.
2. Configure `PROJECT_SENDGRID_ENABLED=true`, `PROJECT_SENDGRID_REGION=us` (or `eu`) and `PROJECT_SENDGRID_API_KEY`. The key needs Mail Send plus read access for verified senders, unsubscribe groups and suppressions. The adapter uses only the fixed official regional API host, with redirects rejected.
3. Enable each intended business using `PROJECT_SENDGRID_ALLCO_ENABLED` or `PROJECT_SENDGRID_HUASHENG_ENABLED`. Set that prefix’s `SENDER_ID`, `FROM_EMAIL` and `UNSUBSCRIBE_GROUP_ID` to existing verified project records. Enabled businesses must have distinct sender IDs, from addresses and groups. This business binding is an owner-reviewed configuration; it does not independently prove company ownership.
4. In SendGrid, configure the Event Webhook for `PUBLIC_ORIGIN/api/delivery/sendgrid/events` and enable signature verification. Store its base64 P-256 DER/SPKI verification key as `PROJECT_SENDGRID_EVENT_PUBLIC_KEY`. Subscribe to processed, deferred, delivered, bounce, dropped, spam report, unsubscribe and group unsubscribe events. Retain the previous public key in `PROJECT_SENDGRID_EVENT_PUBLIC_KEY_PREVIOUS` during rotation for late receipts. Never place the API key in a callback URL.
5. In **HITL review → Project email delivery**, acknowledge and run the free sender/group check. Inspect the business, from/reply address, postal footer and unsubscribe group, then confirm the identity and callback setup. Checks expire after 15 minutes. A changed sender/footer/configuration requires rechecking and fresh exact message review.
6. Save one recipient, choose **Live email · SendGrid**, review sources and the exact sender/footer, and approve that version. The send button remains disabled until its separate final checkbox is checked. No background queue, scheduled send or automatic follow-up exists.
7. For a controlled project test, inspect both provider records and the portal’s immutable receipt. HTTP 202 means accepted; a matched signed delivered event means provider-reported delivery. Neither proves an inbox placement, human reading, reply, consent or buying authority. Verify actual callback reachability and suppression behavior before broader use.

Disabling live delivery prevents new submissions. Retain event public keys and attempt history so delayed signed opt-outs can still apply. Campaign reset preserves delivery records, wallet accounting and provider restrictions. Never delete pending reservations or edit persisted attempts to force a resend.

## Operations and limits

- New submissions are limited to five per business per minute and 500 stored attempts per business. HTTP request replay returns the saved attempt and does not POST again, including after campaign reset. Full delivery history is retained; the desktop shows the latest 20 attempts and latest 100 matched events per attempt.
- Definite provider rejections refund local credit once and invalidate approval. Ambiguous status, connection failure or restart during transmission locks the attempt and retains one reserved local credit. There is no timeout refund or local close/resend action. A matched signed receipt can resolve acceptance; otherwise operator/provider investigation is necessary.
- Signed events verify timestamp plus raw body before parsing. Dispatch/business/recipient/message identity must match; duplicate event IDs do not repeat settlement or stage advancement. Open/click tracking is disabled and those events are ignored. Repeated processed/deferred events cannot regress terminal delivery status.
- Bounce, complaint and opt-out events restrict that address in the same business, clear editable unsent recipients and revoke their approvals. Provider suppression is checked before each POST and cannot be removed with a manual preference release. This is a conservative local processing restriction, not a full consent-management service.
- A signed receipt contradicting a definitive rejection blocks further live mail for investigation. Unknown outcomes are never retried automatically. The provider API does not supply a transaction shared with local SQLite; persisting before the single POST prevents this application from replaying an uncertain send, but cannot prove provider-side exactly-once delivery.
- One accepted email costs one local credit. Optional configured Flexprice metering reserves pending usage before transmission and queues a single `outreach_sent` / `delivery_mode=live` usage event only after provider acceptance. Dry runs retain their separate event label. Unknown acceptance stays reserved; rejection refunds local credit. Provider charges/refunds and processed price correctness still require real project verification.
- Accepted mail advances only a currently Matched account to Contacted. Signed delivery receipts update the native outreach node and desktop polling without manufacturing replies or moving later stages backward. Reply ingestion and real CRM synchronization remain future work.
